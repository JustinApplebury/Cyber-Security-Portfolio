# TryHackMe Phantom Fob

> **Room:** [TryHackMe – Phantom Fob](https://tryhackme.com/room/phantomfob)

## Overview

The challenge involves observing CAN traffic generated by a vehicle key fob and forging the missing Unlock command. The web dashboard exposes Lock, Horn, and Immobiliser controls, but intentionally omits Unlock.

## Initial enumeration

The target exposed:

- A web dashboard on TCP port `8080`
- A `socketcand` CAN-over-TCP service on TCP port `29536`

Install the required Python CAN library:

```bash
sudo apt update
sudo apt install -y python3-can
```

The system Python interpreter was used:

```bash
/usr/bin/python3
```

## Accessing CAN traffic

The remote CAN bus was accessed with `python-can`:

```python
import can

bus = can.Bus(
    interface="socketcand",
    host="<TARGET_IP>",
    port=29536,
    channel="can0",
)
```

The CAN stream was initially noisy, so traffic was filtered by identifying frames emitted immediately after pressing each dashboard control.

## Identifying the command frame

The action-related frame used CAN ID `0x44D`:

```text
LOCK          .. .. .. BD .. 2A 04 77
HORN          .. .. .. BD .. 2A C8 77
IMMOB_ARM     .. .. .. BD .. 2A 92 77
IMMOB_DISARM  .. .. .. BD .. 2A F7 77
```

Byte 6 was the command selector. The other relevant fields changed between frames.

The dashboard’s Server-Sent Events endpoint provided reliable validation:

```bash
curl -sN http://<TARGET_IP>:8080/events
```

For example:

- Immobiliser Arm changed `"immob"` to `true`
- Immobiliser Disarm changed `"immob"` to `false`
- A successful Unlock changed `"locked"` to `false` and released the flag

## Rolling counter and checksum

Repeated frames for the same command showed that byte 0 increments by one. Comparing consecutive samples revealed this relationship:

```text
Δbyte4 = Δbyte1 + Δbyte2 + 1  (mod 256)
```

Since byte 0 also increments by one, byte 4 can be calculated as:

```text
byte4 = (byte0 + byte1 + byte2 + byte6 + 0x05) & 0xff
```

The next valid frame required incrementing byte 0:

```text
byte0_next = (byte0_current + 1) & 0xff
```

## Forging Unlock

A fresh valid frame was captured, then the following fields were constructed:

1. Increment byte 0.
2. Replace byte 6 with candidate command selectors.
3. Recalculate byte 4 using the checksum formula.
4. Inject the forged frame on CAN ID `0x44D`.
5. Monitor `/events` for `"locked": false` or a non-null flag.

The valid Unlock selector was found through a controlled selector search while preserving the rolling state. The final frame successfully unlocked the vehicle and released the challenge flag.

## Lessons learned

- CAN traffic is extremely noisy; filter by arbitration ID and action timing.
- Do not assume a changing field is cryptographic. Compare consecutive frames mathematically.
- Rolling counters must be advanced correctly when forging the next frame.
- The dashboard’s SSE endpoint is useful for validating CAN mutations without relying on visual observation.
